# Asset Conventions — CLAUSRTS

## 1. Folder correlation

Every entity kind has one Go file and one matching PNG:

```
entities/tank.go   <──>  assets/tank.png
entities/infantry.go   <──>  assets/infantry.png
entities/drone.go      <──>  assets/drone.png
...
```

- Units are 32×32 px (one tile), aligned to face **up (+Y → facing north)** in
  the source image so rotation math is trivial.
- Buildings are 32×32 px (one tile) for now; multi-tile buildings may be added
  later with `assets/<name>_2x2.png`-style naming.
- Terrain tiles are `assets/terrain/<name>.png` (grass, road, forest, urban,
  water, mountain).

## 2. Rotation

Each entity rotates toward the tile it faces, but **how** is custom per kind:

| Kind | Rotation strategy |
|---|---|
| Infantry | Rotate the whole image toward the facing tile. |
| Tank | Later: static hull + rotate the turret/cannon only. |
| Artillery | Later: static chassis + rotate the barrel. |
| Drone | Rotate the whole image (omni-directional flight). |
| Cyber / GPS / Scrambler / Air defense | Rotate the whole image. |
| Buildings | No rotation. |

The per-kind hook is the `drawUnit` switch in `renderers`; the default is
"rotate whole image toward facing".

## 3. Placeholders

Placeholders are generated by `cmd/genassets` as simple geometric shapes with a
distinct fill color and a direction wedge so rotation is visible. Replace the
PNGs in place with real art later — no code change required, since loading goes
through `assets.Image(key)`.

## 4. Loading

- `assets` uses `//go:embed`.
- Runtime access: `assets.Image("tank")` → `*ebiten.Image`.
- Load via `ebitenutil.NewImageFromFileSystem(embedFS, "tank.png")`.

## 5. Adding an entity

1. Add `entities/<name>.go` registering a `UnitKind` with `Asset: "name"`.
2. Add `assets/<name>.png` (32×32, facing up).
3. Add the counter relationships to `data` (stats/counters).
4. Optionally add a per-kind `drawUnit` case in `renderers`.
